# 🧰 Диагностика и отладка

Документ описывает средства отладки: флаги окружения, логи оверлея, автопрогоны и диагностику ввода. Всё это включается только флагами окружения — в проде код мёртвый.

## 🎛️ Флаги окружения

| Флаг | Действие |
|---|---|
| `OVERLAY_DEBUG=1` | Логи оверлея подробно: каждое событие и метка |
| `OVERLAY_DEBUG=2` | То же плюс внутренние детали пула (verbose) |
| `NO_COLOR` | Выключает ANSI-цвета в логах |
| `OVERLAY_AUTO_OPEN_MS=N` | Открыть меню через `N` мс после старта |
| `OVERLAY_FIND_CYCLE_MS=N` | Два открытия панели поиска подряд без клика по странице |
| `OVERLAY_FOCUS_DEBUG=1` | Лог владельца фокуса и каждой нажатой клавиши |
| `OVERLAY_PAGE_LOAD_DELAY_MS=N` | Искусственная задержка загрузки страницы оверлея |
| `KONSTRUKTOR_DEVTOOLS=1` или `--devtools` | Открыть DevTools окна при старте |
| `KONSTRUKTOR_EXT_SMOKE=<путь>` | Поставить расширение из папки или `.crx` через `N` мс и выйти |
| `KONSTRUKTOR_PERM_SMOKE=<url>` | Прогон разрешений: открыть страницу, запросить микрофон, разрешить в промпте, запросить снова |
| `KONSTRUKTOR_PERM_SMOKE_MS=N` | Задержка перед прогоном разрешений (по умолчанию 3000) |
| `KONSTRUKTOR_EXT_SMOKE_MS=N` | Задержка перед установкой (по умолчанию 3000) |
| `KONSTRUKTOR_EXT_MENU_MS=N` | Открыть меню расширений через `N` мс после старта |
| `KONSTRUKTOR_EXT_POPUP_MS=N` | Открыть попап первого расширения с `default_popup` через `N` мс |
| `KONSTRUKTOR_APP_QUIT_MS=N` | Корректно завершить приложение через `N` мс |
| `THEME_DEBUG=1` | Лог резолва темы: схема веб-контента и обновления темы ОС |

`OVERLAY_DEBUG` разбирается в `overlay/logger.ts`, остальные флаги — в `diagnostics.ts` и `overlay/pool.ts`. Логи оверлея описаны ниже, задержка загрузки — в [OVERLAY.md](../overlay/OVERLAY.md) (проверка буфера push).

Синтаксис зависит от оболочки. Запись `ФЛАГ=значение npm run dev` работает только в bash. В PowerShell флаг ставят в переменную окружения сессии: `$env:KONSTRUKTOR_EXT_MENU_MS='5000'; npm run dev`; в cmd — `set KONSTRUKTOR_EXT_MENU_MS=5000 && npm run dev`. Electron наследует окружение от процесса `npm`, поэтому переменная доходит до main.

## 📜 Логи оверлея

Логирование живёт в `overlay/logger.ts` и обслуживает всю папку `overlay/` и её потребителей. Категории: `pool`, `session`, `command`, `geometry`, `perf`, `lifecycle`, `error`. В terse-режиме (без `OVERLAY_DEBUG`) видны только `session`, `perf` и `error`.

Уровень читается один раз при загрузке модуля: сменить его на лету нельзя, нужен перезапуск. Кроме `log` модуль отдаёт метки производительности (`mark`, `perf`, `recordOpen`) и сводку (`dumpStats`, `resetStats`), которую используют диагностика и завершение работы.

## 🧪 Автопрогоны

`setupDiagnostics` умеет воспроизводить несколько сценариев без участия пользователя:

- **Автооткрытие меню** (`OVERLAY_AUTO_OPEN_MS`) — чтобы попасть в окно искусственной задержки загрузки страницы, не гоняя мышью. Окно берётся из `bootState`, а не из `BrowserWindow.getAllWindows()[0]`: в списке первым может оказаться оверлей с bounds `1x1` за экраном, и меню уехало бы в отрицательные координаты.
- **Цикл панели поиска** (`OVERLAY_FIND_CYCLE_MS`) — два открытия подряд, второе сразу после закрытия первого и **без клика** по странице. Проверяет, что после закрытия фокус вернулся сам: раньше Ctrl+F уходил в прозрачное окно оверлея и панель не открывалась до клика по странице.
- **Установка расширения** (`KONSTRUKTOR_EXT_SMOKE`) — проверяет всю цепочку системы расширений разом: распаковку контейнера, переписывание манифеста, загрузку в сессию, запуск фона и работу loopback-моста. В лог уходят порт моста, результат установки и полное состояние реестра с `electronId` и ошибкой загрузки. Закрепляет ИМЕННО установленное расширение (по `id` из результата, а не первый в списке) и выходит через `app.quit()`, чтобы хук `before-quit` снял регистрации. Подробности — в [EXTENSIONS.md](../extensions/EXTENSIONS.md).
- **Меню расширений** (`KONSTRUKTOR_EXT_MENU_MS`) — открывает меню расширений тем же вызовом, что и кнопка-пазл, спустя `N` мс. Нужно потому, что без него меню не проверить без мыши, а его закрытие по чужому blur'у видно только в логе. Перед открытием печатает `userData`, полное состояние реестра и модель меню — по ним видно профиль (`userData`) и состав строк, что снимает путаницу «расширение пропало» при отладке. Так были найдены обе причины невидимого меню: вид `extensions` не забирал фокус, и `propsFor` в renderer не собирал пропсы для этого вида.
- **Попап расширения** (`KONSTRUKTOR_EXT_POPUP_MS`) — открывает попап первого расширения с `default_popup` тем же вызовом, что и клик по значку, спустя `N` мс. Печатает имя расширения и URL активной вкладки. Нужно, чтобы проверить чужой попап (headless) и увидеть, дошли ли до его страницы вкладка и фон; так найдены обе причины «not a website» у uBlock (tabs.query от лица попапа и первое sendMessage к ещё не поднявшемуся service worker'у).
- **Прогон разрешений** (`KONSTRUKTOR_PERM_SMOKE=<url>`) — открывает страницу в новой вкладке, просит у неё микрофон, нажимает «Разрешить» в промпте и просит ещё раз. Печатает URL, результат обоих запросов (`GRANTED`/`DENIED:<имя>`), содержимое `permissions.json`, текст страницы разрешений (`konstruktor://permissions`), ОФОРМЛЕНИЕ её страницы (`page layout`: вычисленные размер и цвет подзаголовка, «раздел проверки выше кнопки сброса», тег и размер квадрата корзины — иначе тусклый мелкий заголовок, переставленные блоки и кнопка без рамки на глаз не ловятся), разметку меню бейджа (`menu layout`: текст, тег строки, `plain`, `disabled`, `heading`, цвет, размер, тег и габариты корзины каждого пункта — по этому видно, что строка — не кнопка, а корзина — именно кнопка) и результат снятия ОДНОЙ области (её решение должно пропасть, остальные — остаться) — и со страницы, и из меню, после чего убирает решения и выходит; профиль разработчика прогон не засоряет. Проверяет всю цепочку: обработчик ЗАПРОСА вызывается при отказе обработчика ПРОВЕРКИ (иначе промпта не было бы вовсе), ответ доходит до страницы, решение ложится в хранилище, повторный запрос идёт без промпта. Страница обязана быть в защищённом контексте (`http://localhost` или `https`), иначе `navigator.mediaDevices` не существует. Запуск: `KONSTRUKTOR_PERM_SMOKE=http://localhost:5173/ npm run dev` при поднятом Vite-сервере.
- **Корректный выход** (`KONSTRUKTOR_APP_QUIT_MS`) — вызывает `app.quit()`, а не `app.exit()`, спустя `N` мс. Проверяет хук `before-quit`, который выгружает расширения перед выходом: без выгрузки следующий старт поднимает их воркеры в урезанном контексте и фон падает (см. [EXTENSIONS.md](../extensions/EXTENSIONS.md)).

## 🔍 Диагностика ввода

При `OVERLAY_FOCUS_DEBUG` диагностика подписывается на `before-input-event` всех `webContents`: и окон (`window:<id>`), и view вкладок (`view-under:<id>`), обновляя список каждые 500 мс, и раз в секунду логирует текущего владельца фокуса.

Ловушка, стоившая неверных гипотез: `webContents` вкладки — это `WebContentsView`, и он **не входит** в `BrowserWindow.getAllWindows()`. Подписка только на окна показывает ложное «ввода нет», потому что клавиатуру принимает именно view. Обход идёт по `win.contentView.children`, у которых есть `webContents`.

## 🧹 Границы

Диагностика отделена от продуктового кода: всё под флагами окружения, и без флагов ветки не выполняются. Флаги не входят в обычный `OVERLAY_DEBUG` — они либо слишком шумные (лог каждой клавиши), либо воспроизводят конкретный сценарий.
