# 🌐 Локализация

Документ описывает систему перевода интерфейса: движок, каталоги, формулы ключей, доставку языка по поверхностям, логи и инструменты проверки. Английский — язык-источник, первый целевой язык — русский; реестр языков расширяемый.

## 🎯 Устройство

Движок — i18next (одинаковый синтаксис во всех процессах) плюс i18next-vue для Vue-приложений. Каталоги лежат в `locales/*.json`, вшиваются в сборки всех процессов, файловое чтение в рантайме не нужно — внутренние страницы и оффлайн-режим работают без сети.

| Поверхность                           | Точка входа                                       | Как получает язык                                                       |
| ------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------- |
| Main (меню, диалоги, тосты, счётчики) | `src/main/i18n.ts` → `t()`                        | `initI18n()` до первого окна, смена в `settings:save`                   |
| Shell (`renderer`)                    | `src/renderer/i18n.ts`, `$t` / `useTranslation()` | стартовое чтение настроек, подписка `settings:changed` с полем `locale` |
| Overlay (FindBar, диалог иконки)      | тот же `renderer/i18n.ts`                         | поле `language` в `PushMessage`                                         |
| Внутренние страницы                   | `build*Page(lang)` + встроенный `tr()`            | язык запекается в HTML на каждый запрос                                 |

```mermaid
flowchart LR
  SET[settings.locale: auto | код] -->|resolveLocale| MI[main: initI18n / setLocalePreference]
  MI -->|t\(\)| MENU[меню, диалоги, тосты]
  MI -->|settings:changed + locale| SH[shell]
  MI -->|PushMessage.language| OV[overlay]
  MI -->|build*Page\(lang\)| IP[внутренние страницы]
  SH -->|resolveLocale + navigator.language| LANG[i18next.changeLanguage]
  OV --> LANG
```

## 📁 Файлы

```
src/shared/i18n/
  locales/en.json    язык-источник: все новые строки здесь
  languages.ts       реестр LANGUAGES: код, Intl-локаль, подпись
  index.ts           resolveLocale, buildResources, i18nOptions, типы ключей
  pageRuntime.ts     window.tr + запекание каталога в страницы
  I18N.md            этот документ
src/main/i18n.ts     initI18n, setLocalePreference, currentLang, t()
src/renderer/i18n.ts initI18n, changeLanguage, installI18n, t()
scripts/i18n-check.mjs   сверка каталогов с en.json
scripts/i18n-scan.mjs    извлечение ключей из кода
```

`buildResources()` склеивает каждый каталог с английским (deep-merge): непереведённый ключ отдаёт английский текст, а `missingKeyHandler` срабатывает только на реально отсутствующие ключи — опечатки, а не доли непереводов.

## 📖 Ключи и формат

- Вложенность по поверхностям: `menu.*`, `tabs.*`, `groups.*`, `dialogs.*`, `window.*`, `icon.*`, `toast.*`, `find.*`, `zoom.*`, `addressBar.*`, `bookmarks.*`, `shell.*`, `settings.*`, `history.*`, `downloads.*`, `start.*`, `internal.*`, `common.*`.
- Интерполяция i18next: `"find.counter": "{{active}} of {{total}}"`, вызов `t('find.counter', { active, total })`.
- Множественное число через суффиксы с `count`: `_one`/`_other` для английского, полный набор категорий языка (`_one`/`_few`/`_many`/`_other`) для русского. Вызов — по базовому ключу: `t('history.groupCount', { count })`.
- Контекст задаётся именем ключа (`groups.menu.pinToBookmarks`): переводитель видит английский источник рядом со значением в редакторе.
- Конкатенация переводимых фрагментов не используется — только именованные параметры.
- Настройки: `fallbackLng: 'en'`, `returnNull: false`, `returnEmptyString: false` — пустое или отсутствующее значение показывает английский текст.
- Значения со вставками HTML (`settings.footer`, `settings.themeHint`, `start.cta`) уходят только в статическую разметку страниц при сборке `t()`; динамические скрипты страниц читают каталог через `tr()` и вставляют текст.

Пример ключа целиком:

```json
{
  "history": {
    "groupCount_one": "{{count}} visit",
    "groupCount_other": "{{count}} visits",
    "today": "Today"
  }
}
```

## ✍️ Как писать перевод в коде

- **Main** — `import { t } from './i18n'`. После `initI18n()` вызов синхронен, меню собираются без await (контекст требует синхронности, как у `getSettingsSync()`).
- **Shell и overlay, шаблон** — `$t('key')`: записывает реактивную зависимость, компонент перерисовывается при смене языка.
- **Shell и overlay, `<script setup>`** — `useTranslation()` из i18next-vue либо `import { t } from '.../i18n'`; второй вариант для вызовов вне рендера (обработчики, хелперы вроде `shortTitle`).
- **Внутренние страницы** — статические строки: `t()` при сборке тела; динамические строки внутри `<script>`: `tr('key', { params })`. Для дат страницы используют `window.__I18N_INTL__` (Intl-локаль из реестра) вместо `undefined`.

Порядок в точках входа обязателен: `initI18n()` до `app.mount()` — i18next-vue отдаёт пустую строку для неготового i18next, и первый кадр показал бы пустые тултипы.

## 🌍 Детект и переключение

Значение настройки `locale` — `'auto' | код из LANGUAGES`, дефолт `'auto'`. `resolveLocale(pref, systemLocale)` резолвит `auto` по локали системы (`app.getLocale()` в main, `navigator.language` в shell), незнакомый код деградирует до `en`. Существующие `settings.json` продолжают работать без миграции.

Переключение: страница настроек → `settings:save` → main меняет язык до рассылки → шлёт `settings:changed` с полем `locale` (shell резолвит его сам) и пуш overlay с `language` при следующем открытии. Внутренние страницы обновляются перезагрузкой вкладки — состояние страниц сохраняется сразу, reload безопасен.

## 📜 Логи

В dev-сборке (`import.meta.env.DEV`) с префиксом `[i18n]`:

- `[i18n] init lang=en` — инициализация процесса (main — в терминал, renderer — в консоль);
- `[i18n] language -> ru` — смена языка после `changeLanguage`;
- `[i18n] missing: <key> (<языки>)` — ключ отсутствует во всех каталогах: опечатка в вызове `t()` или ключ не добавлен в `en.json`.

Консоль renderer до терминала докатывается ненадёжно (Chromium-брандмауэр логов): при разборе проблем логи shell читать через DevTools окна, а не только через stdout.

## 🧪 Инструменты

- **i18n Ally** (VS Code) — английский источник рядом со значением в каталоге, подсветка отсутствующих ключей, перевод по хоткею.
- `npm run i18n:check` — сверяет каждый каталог с `en.json`: отсутствующие ключи, неполные наборы суффиксов множественного числа для категорий языка (`Intl.PluralRules`), лишние ключи. Ненулевой код выхода при любой проблеме.
- `npm run i18n:scan` — извлекает `t(...)`/`$t(...)`/`tr(...)` с литеральными ключами из всех `.ts`/`.vue` файлов `src`: ключ без каталога — ошибка, ключ каталога без вызова — предупреждение.
- **Типы ключей** — `CustomTypeOptions.resources` в `shared/i18n/index.ts` строится из `typeof en.json`: опечатка в ключе роняет `npm run typecheck`, автокомплит подсказывает имена.

## ➕ Добавление языка

1. Скопировать `en.json` → `<код>.json` и перевести (i18n Ally).
2. Добавить запись в `LANGUAGES` (`languages.ts`): код, Intl-локаль, подпись.
3. `npm run i18n:check` — убедиться в полноте.

Код не меняется: каталог подключается glob'ом, селектор языка в настройках и форматтеры дат строятся из реестра.

## ⚠️ Особенности

- Переводятся пользовательские строки. Dev-only пункты (отладочный `Debug`, авто-открытие меню), технические идентификаторы и сохранённые данные (имена групп, плитки, URL) остаются как есть — дефолтное имя группы `Group` переводится в источнике, но записанные в `groups.json` имена при смене языка не меняются.
- Нативный file-диалог (`dialog.showOpenDialog`) получает переведённые заголовок и фильтры через `t()`, сам диалог рисует ОС на языке системы.
- Смена языка применяется к открытым поверхностям через следующий push: overlay узнаёт язык из `PushMessage.language` при открытии.
