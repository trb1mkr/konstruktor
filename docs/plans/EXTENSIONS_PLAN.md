# 🧩 Расширения: план на будущее

Система расширений построена и описана в `src/main/extensions/EXTENSIONS.md`: установка из папки и `.crx`, реестр, шим совместимости с loopback-мостом, собственная платформа `konstruktor.*`, страница `konstruktor://extensions`, меню расширений с закреплением, попапы в отдельном окне, клавиатурные команды и автообновление. Здесь остаётся только незакрытое.

## 🚧 Незакрытое из основного объёма

- **Экран прав до включения.** Расширения, которые блокируют запросы или работают контент-скриптами на всех сайтах, должны получать согласие пользователя до первого запуска, а не только показывать список запрошенных прав на карточке. Связано с планом блокировки — `docs/plans/DNR_BLOCKING_PLAN.md`.
- **Установка по URL.** Установка и обновление прямо из Chrome Web Store по идентификатору. Выбранный путь — `electron-chrome-web-store` (MIT): закрывает скачивание, распаковку и проверку обновлений, поэтому своей возни с веб-магазином не будет.
- **Квоты `konstruktor.storage`.** Объём хранилища своего расширения сейчас не ограничен: нужен предел и понятная ошибка при его достижении.

## 🧩 Собственная экосистема: что расширить

- **Вклад UI-компонентов в shell.** `registerComponent` из `renderer/core/registry.ts` принимает собранный JS-модуль, но расширение пока не может принести свою панель в интерфейс браузера. Нужен контракт на монтирование и размонтирование — иначе такой компонент нельзя будет убрать.
- **Объявление своей страницы как «настройки».** Страница расширения доступна по `konstruktor://ext/<id>/<файл>`, но как расширение помечает её настройками (чтобы открывалась отдельной кнопкой из карточки) — не решено.

## 🔐 Проверка подлинности

- **Проверка подписи CRX3.** Сейчас расширения ставятся с пометкой «неподписанное». Разбор ASN.1 через `node:crypto` выполним, но требует работы с форматом подписи и цепочкой сертификатов. Нужен, чтобы отличать подлинный `.crx` от изменённого, и чтобы убрать пометку.

## 🧰 Кандидаты на пересмотр

- **`electron-chrome-extensions` (GPL-3).** Мог бы заменить часть своего шима (`tabs`, `windows`, `cookies`, `notifications`, `webNavigation`, `webRequest`) и даёт готовый `<browser-action-list>`. Не взят: слой совместимости уже работает, а GPL-3 накладывает обязательства на распространение. Пересматривать, только если паритет по `chrome.*` станет важнее объёма своего кода — у пакета есть и свои ограничения (фон всегда постоянный, `webNavigation.onDOMContentLoaded` только для главного фрейма, прелоад для service worker требует песочницы, а свой `webRequest` глушит `chrome.webRequest` расширения).
