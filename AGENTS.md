# 🤝 Контекст для агента

Документ задаёт порядок работы в репозитории: с чего начать, какие документы читать под задачу и как проверять результат. Постоянные правила проекта описаны в документации, а не здесь; этот файл — карта документации и рабочий протокол.

## 🚀 Обязательный порядок

Перед выполнение поставленной задачи в этом репозитории:

1. Прочитать `README.md`. Это входная точка: стек, команды запуска, точки кастомизации и — главное — список ссылок на всю остальную документацию.
2. Определить, к какой системе относится задача, и открыть соответствующие документы из списка `README.md`. Внутри них лежит порядок имплементации: инварианты, порядок вызовов, принятые соглашения и уже накопленные грабли.
3. Прочитать найденные документы целиком, а не по поиску. Документы описывают текущее поведение, и строка из соседнего абзаца меняет то, как правильно реализовать задачу.
4. Сверить выбранный подход с кодом: документация описывает замысел, код — состояние.

## 🧭 Как выбирать документ по задаче

Задача почти всегда затрагивает main, renderer и мост одновременно. Ориентир — по тому, что меняется визуально и по чему идёт IPC:

| Признак задачи | Обязательные документы |
|---|---|
| Вкладки, группы, панель вкладок, окно | `WINDOWS_TABS.md`, `STDLIB.md`, `SHELL_LAYOUT.md` |
| Меню, диалог, тост, поиск, иконка | `OVERLAY.md`, `OVERLAY_UI.md`, `SHELL_BRIDGE.md` |
| Кнопки окна, рамка, прозрачность, скругление | `SHELL_LAYOUT.md`, `TROUBLESHOOTING.md` |
| Тема, оформление, цвета | `THEMES.md`, `CORE_STATE.md` |
| Настройки, история, загрузки, плитки | `STORES.md`, `INTERNAL_PAGES.md`, `VIEW_BRIDGE.md` |
| `konstruktor://`, страницы без сайта | `INTERNAL_PAGES.md`, `VIEW_BRIDGE.md` |
| Поиск по странице | `FIND.md`, `OVERLAY_UI.md` |
| Клик не срабатывает, фокус не тот, видно старый кадр | `TROUBLESHOOTING.md` первым, потом профильный документ |
| Новая документация или её правка | `docs/DOCS.md`, плюс `README.md` для обновления списка ссылок |

Если задача не ложится ни в одну строку таблицы — начинать с `docs/ARCHITECTURE.md`, он даёт карту модулей и ссылки на все остальные документы.

## 🔎 Что важно помнить при правке

Документы проекта содержат инварианты и уже решённые проблемы, а не только описание. Перед реализацией стоит проверить их на месте — это дешевле, чем повторить выясненное заново:

- **Единый ряд панели.** Токены `t:<id>` и `g:<instanceId>` одного ранга; вкладка внутри группы токена не имеет. Нарушение даёт невидимую группу или дубль. Проверка — `checkStripInvariant`.
- **Порядок клонирования.** Группы копируются до вкладок, затем `reorderStrip` с подменой токенов `t:<исходный> → t:<копия>`. Пропуск любого шага ломает порядок панели в новом окне.
- **Размер overlay-панели** приходит из renderer через `ResizeObserver` и канал `overlay:measured`, а не считается формулой в main. `firstElementChild` поверхности, не `.overlay-root`.
- **Показ overlay** идёт только после подтверждения `overlay:painted`, иначе видны пункты предыдущего меню. Таймауты разделены: `PAINT_BUDGET_MS` — только лог, `PAINT_TIMEOUT_MS` — отмена показа.
- **Скрытие overlay** обеспечивают три независимых слоя: `v-if` в renderer, `setOpacity(0)`, `setIgnoreMouseEvents(true)`. На Linux `setOpacity` не действует, поэтому размонтирование подтверждается отдельно через `overlay:unmounted`.
- **Сессии overlay** защищены `sessionId`-токеном, который проверяется на трёх сторонах. Счётчик монотонно растёт, старый токен нельзя сравнивать как «совпадает».
- **Drag-область заголовка не используется** намеренно: на Windows она перехватывает правый клик и отдаёт его системному меню окна. Окно тащится через `screenX/screenY`, а `window:drag-start` — синхронный вызов, потому что ответ нужен до первого `mousemove`.
- **Партиции.** `persist:konstruktor` для обычных окон, `incognito-mem` для приватных; одна `WebContentsView` принадлежит одному родителю, клон создаёт свои view с той же партицией.
- **Роутинг `konstruktor://`** регистрируется на трёх сессиях, а схема объявляется privileged до `ready`.
- **Изоляция контекста.** Preload собирается в `cjs`, `nodeIntegration` выключен, в renderer нет `require('electron')`. Для preload view используется `registerPreloadScript`, а не `webPreferences.preload`.
- **Синхронное чтение настроек** на холодном старте — `readSettingsFileSync`, без него окно получает пустые настройки.

## 🧪 Проверка результата

```sh
npm run typecheck   # vue-tsc --noEmit
npm run build       # electron-vite build
npm run dev         # ручная проверка в окне приложения
```

`npm test` в проекте не существует: скрипт-заглушка `echo "Error: no test specified" && exit 1` завершается с ошибкой. Считать его успешным прогоном нельзя. Проверка изменений в UI идёт через `npm run dev`.
